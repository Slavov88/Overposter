# Hosted collaboration boundary

Public hosted collaboration is not enabled. `OVERPOSTER_MODE=hosted` fails startup. The local API still binds to loopback, and it has no site account sessions. A standalone Linux sandbox worker prototype can be exercised separately; it is not connected to the API.

## Test-only foundation

A loopback test harness is available with `NODE_ENV=test`, `OVERPOSTER_MODE=test-hosted`, and `OVERPOSTER_TEST_IDENTITIES=1`. The `X-Overposter-Test-Subject` header supplies an exact simulated identity for API tests. Browser tests call `POST /api/test-session` to set a test-only, HttpOnly, SameSite cookie. Either mechanism lets a test choose any subject and is **not authentication**. The startup guard rejects this mode without both test flags.

Membership is stored outside editable project source in versioned `.overposter/access.sqlite`. Legacy `.overposter/access/<id>.json` grants require the backed-up migration command, are copied once, and are retained for rollback; see [membership migration](ACCESS_MIGRATION.md). Owners manage members and deletion; editors can write source and checkpoints; viewers can read. Every project REST route checks membership. A viewer's WebSocket updates are rejected, and revocation closes affected sockets. A `PUT` to existing shared source requires its current ETag.

The `/api/projects/:id/collab?path=...` WebSocket accepts Yjs binary updates for editable text files. The server persists Yjs state under `.overposter/collaboration/` and flushes text to source. It sends the full document state on connect; later binary frames are Yjs updates. JSON `presence` frames carry the server-validated subject and optional character cursor. A `saved` control frame acknowledges persistence of a binary update. The browser waits for that acknowledgment before navigating, exporting, or asking for a checkpoint. Checkpoints, restores, source reads and exports wait for queued document writes. The tests cover two browser editors, presence, roles, convergence, viewer write rejection, revocation, restart recovery, and source history.

The browser editor now uses Yjs in test mode, shows collaborator names and cursor markers, reports connection and persistence state, and offers owner-only access management by exact test subject. Disconnected editors become read-only until reconnection. This is not a production invitation or account lookup flow. Identity resolution now has a local/test provider interface, but the test identity mechanisms are not a site account adapter. Production still needs the documented site account contract, real server-side sessions, a production subject mapping and membership migration, cross-process transaction and reconnection design, and a separate isolated TeX worker. The test harness is not a deployable multiuser service.

## Production acceptance gates

The planned account adapter needs a separate `overposter` grant, validated issuer and immutable subject, server-side sessions, state/PKCE where required, and CSRF protection. Membership remains project specific; every REST route, PDF/download route and WebSocket join/update must check it. Revocation must disconnect affected sockets.

Hosted TeX needs a separate unprivileged VM or restricted Linux worker with no network, per-job mounts, CPU/RAM/time quotas, cancellation, limited concurrency, a secret-free environment, redacted logs, pinned source revision and authenticated artifact delivery. The web server must have no fallback to direct local XeLaTeX. The standalone `pnpm worker:run <source.zip> <sha256> <private-artifact-dir>` prototype verifies a SHA-256 pinned ZIP, rejects unsafe entries, and uses `prlimit` plus bubblewrap with no network and narrow read-only mounts for XeLaTeX and xdvipdfmx. It returns only a bounded PDF and preflight report, with raw compiler logs suppressed. ZIP validation tests run locally; Linux CI is configured to exercise a real sandbox build. It is not an authenticated service, and host-level filesystem, concurrency, CPU/memory/disk and process controls need deployment validation before any public job can use it. Preflight executes on the dedicated worker host outside bubblewrap, so the host must contain no account secrets or project database.

## Manual cross-app reference

An owner may record an Overroot project ID and HTTPS deep link in the Overposter project. The URL origin is restricted by `OVERPOSTER_OVERROOT_ORIGIN` (default `https://overroot.toni.foo`). A viewer may open the link with their own Overroot access; Overposter does not verify that access. The record includes the local actor and timestamp. Version checks reject stale edits to the reference. No remote request, membership transfer, source sync, or credential reuse occurs. The reference is outside the source ZIP and Git poster checkpoints; transfer still uses an explicit ZIP export/import and import trust review. A real authenticated link requires Toni's scoped project API and approval in both services.
